# GRU-Network-Intrusion-Detection

A GRU based Deep Learning Model for detecting malicious network traffic (benign vs. attack) using the CIC-IDS2017 dataset.

# Network Intrusion Detection Using GRU (CIC-IDS2017)

## Project Overview

This project implements a Network Intrusion Detection System (NIDS) using a Gated Recurrent Unit (GRU) neural network.

Instead of judging each network flow on its own, the model reads a window of 10 consecutive flow records and learns whether the traffic is benign or malicious. The project explores how sequence-aware deep learning can support analysts in spotting attacks such as DoS, DDoS, brute force, port scans and botnets.

## Dataset

- Dataset: CIC-IDS2017 (Canadian Institute for Cybersecurity)
- Type: network **flow records** (not raw packets), extracted with CICFlowMeter
- Size: about 2.8 million records with roughly 78 numeric features
- Labels: `BENIGN` mapped to 0, every attack type mapped to 1 (binary classification)
- Download: https://www.unb.ca/cic/datasets/ids-2017.html
- The dataset is **not** included in this repository (it is large). See `data/README.md`.

## Methodology

1. Load the CIC-IDS2017 CSV files in capture order (Monday to Friday).
2. Drop identifier columns (Flow ID, IP addresses, Timestamp).
3. Convert features to numbers; replace missing/infinite values with the training median.
4. Split in order: first 80% of rows for training, last 20% for testing; the last 10% of the training part is used for validation. Rows are not shuffled.
5. Scale features with `StandardScaler` fitted on training rows only (no data leakage).
6. Build sliding windows of 10 consecutive records; each window takes the label of its last record. Windows are built inside each split so none crosses a split border.
7. Train the GRU with class weights and early stopping.
8. Evaluate on the unseen test split using accuracy, precision, recall, F1-score and the confusion matrix.

## GRU Architecture

| Layer | Details |
|---|---|
| Input | 10 records x F features |
| GRU | 64 units |
| Dropout | 0.3 |
| Dense | 32 units, ReLU |
| Dense (output) | 1 unit, Sigmoid (score >= 0.5 means malicious) |

Optimizer: Adam. Loss: binary cross-entropy.

## Evaluation Metrics

Accuracy alone can be misleading on imbalanced traffic, so the project reports:

- **Precision**: of the flows flagged as attacks, how many were real attacks
- **Recall**: of the real attacks, how many were caught
- **F1-score**: balance between precision and recall
- **Confusion matrix**: true/false positives and negatives

Results are generated by running the script and are saved in `results/`.

## Limitations

- CSV row order is assumed to be time order; it does not prove a live session.
- Binary labels hide which attack type occurred.
- Only one 2017 lab dataset is used; real networks may behave differently.
- Attacks occur in time blocks, so a time-ordered split can be uneven.

## How to Run

1. Clone the repository:
   ```bash
   git clone https://github.com/<your-username>/GRU-Network-Intrusion-Detection.git
   cd GRU-Network-Intrusion-Detection
   ```
2. Install dependencies:
   ```bash
   pip install -r requirements.txt
   ```
3. Download CIC-IDS2017 and put the CSV files in the `data/` folder.
4. Run:
   ```bash
   python gru_network_intrusion_detection.py
   ```
5. Check `results/` for `metrics.csv`, `confusion_matrix.png` and `training_curves.png`.

## Conclusion

This project demonstrates how a GRU can learn from sequences of network flow records to separate benign traffic from malicious traffic, and why precision, recall and F1-score matter more than accuracy for intrusion detection.
